# v030-u26-mtp4-q8 — Recommended (current production)

The **current recommended production configuration** after the llama.cpp **v0.3.0 + ubuntu26.04 base** suite passed on the upgrade Intel stack (compute-runtime 26.31.39395.13, `:stable` image). Keeps the Q8 quantized MTP stack that unlocks 128k, and moves the speculative context to **MTP4** (n-max 4) with thinking enabled.

- **Base image:** `intel/deep-learning-essentials:2026.1.2-devel-ubuntu26.04` (bumped from 24.04).
- **Purpose:** Default / production config — full 128k context + MTP4 speculation, stable on the upgrade stack.
- **Draft:** `mtp-Qwen3.8-27B-Q8_0.gguf` (≈3.2 GB), `--spec-type draft-mtp`, `--spec-draft-n-max 4 --spec-draft-p-min 0.1`.
- **Draft KV:** q8_0 (`--spec-draft-type-k/v q8_0`, was f16).
- **Vision:** `mmproj-Qwen3.8-27B-Q8_0.gguf` (≈0.6 GB), CPU via `--no-mmproj-offload`.
- **Context:** 128k (`--ctx-size 131072`).
- **KV cache:** **q8_0** for the main context **and** the MTP draft context.
- **Thinking:** enabled (default; no `--chat-template-kwargs` override).

## Why MTP4 over MTP3

MTP4 does **not** reduce draft acceptance vs MTP3 on the v0.3.0 + q8 stack:

| Config | weighted acceptance | mean len |
|---|---|---|
| **v0.3.0 MTP4 (this config)** | 0.559–0.571 | 3.53 |
| v0.2.0 MTP3 (q8) | 0.567 | 3.04 |

MTP4 mean accepted length (3.53) is longer than MTP3 (3.04) → more tokens accepted per draft block → higher speculative throughput on long generation, with equal-or-better acceptance and identical stability (0 crashes).

## Full launch flags

```bash
-m /models/Qwen3.8-27B-Q4_K_M.gguf \
--mmproj /models/mmproj-Qwen3.8-27B-Q8_0.gguf \
--no-mmproj-offload --image-min-tokens 1024 \
--n-gpu-layers 999 \
--ctx-size 131072 \
--cache-type-k q8_0 --cache-type-v q8_0 \
--flash-attn on \
--spec-type draft-mtp \
--spec-draft-model /models/mtp-Qwen3.8-27B-Q8_0.gguf \
--spec-draft-n-max 4 \
--spec-draft-p-min 0.1 \
--spec-draft-type-k q8_0 --spec-draft-type-v q8_0 \
--port 8080 --host 0.0.0.0
```

The `examples/qwen27b-server.sh` launcher matches this configuration.

## Memory footprint

- Main model 18.9 GB + Q8 MTP draft ≈2.4 GB + mmproj Q8 ≈0.6 GB (CPU) + draft KV q8_0 + 128k q8_0 KV. Fits 32 GB with headroom.
- Direct decode ≈ 25–42 t/s (short context); agent-chain decode ≈ 16–23 t/s (context-dependent).
- Full-suite weighted acceptance 0.57.

## When to use / avoid

- **Use as the default** — v0.3.0 + u26 base, MTP4, 128k stable, thinking on.
- MTP value is on long contiguous generation; deep-context turns still pay a large prefill (TTFT) cost — see the linked report.
- Do **not** switch the draft back to BF16 on this stack at 128k — confirmed crash.
