# mtp4-128k — Max context

- **Purpose:** The **maximum / extreme** configuration — fully enabled MTP at its highest draft count plus the full 128k context. Passes all five text tasks plus three real-vision tests on B70; the only config that currently saturates context *and* MTP on 32 GB.
- **Draft:** `mtp-Qwen3.8-27B-BF16.gguf` (≈5.9 GB), `--spec-type draft-mtp`, `--spec-draft-n-max 4 --spec-draft-p-min 0.1`.
- **Context:** 128k (`--ctx-size 131072`).
- **KV cache:** **q8_0** (`--cache-type-k/v q8_0`).

## Full launch flags

```bash
--m /models/Qwen3.8-27B-Q4_K_M.gguf \
--mmproj /models/mmproj-Qwen3.8-27B-BF16.gguf \
--n-gpu-layers 999 \
--ctx-size 131072 \
--cache-type-k q8_0 --cache-type-v q8_0 \
--flash-attn on \
--spec-type draft-mtp \
--spec-draft-model /models/mtp-Qwen3.8-27B-BF16.gguf \
--spec-draft-n-max 4 \
--spec-draft-p-min 0.1 \
--port 8080 --host 0.0.0.0
```

> The `examples/qwen27b-server.sh` launcher matches this configuration (MTP4 + 128k + q8_0).

Required environment:

```bash
ONEAPI_DEVICE_SELECTOR=level_zero:0
SYCL_CACHE_PERSISTENT=0
ZES_ENABLE_SYSMAN=1
```

## Memory footprint

- Main model 18.9 GB + MTP draft 5.9 GB + 128k KV (q8_0). **Only q8_0 KV fits this inside 32 GB** — f16 KV at 128k with the draft is the confirmed OOM trigger.
- Decode ≈ **36–41 t/s** during agent chains (≈0.88 s TTFT on short prompts), acceptance 0.50–0.58 in long chains.

## When to use / avoid

- **Use when 128k context is required** (very long tool chains).
- Decode is not better than `mtp3-96k` (36–41 vs 33–35 t/s) — 128k buys *context*, not speed. Choose `mtp3-96k` when latency matters more and you don't need the full window.
- Higher `n-max` pushes KV pressure hardest; keep q8_0 KV.
