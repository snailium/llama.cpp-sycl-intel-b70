# mtp3-q8-128k — Recommended (current production)

The **recommended production configuration** for the upgraded Intel stack (compute-runtime 26.31.39395.13, `:stable` image). Quantized Q8 MTP draft + Q8 mmproj give full 128k capability that the BF16 draft cannot reach on the upgrade stack.

- **Purpose:** Default / production config. Full 128k context + MTP speculation, stable on the upgrade stack.
- **Draft:** `mtp-Qwen3.8-27B-Q8_0.gguf` (≈3.2 GB), `--spec-type draft-mtp`, `--spec-draft-n-max 3 --spec-draft-p-min 0.1`.
- **Vision:** `mmproj-Qwen3.8-27B-Q8_0.gguf` (≈0.6 GB), loaded on CPU via `--no-mmproj-offload`.
- **Context:** 128k (`--ctx-size 131072`).
- **KV cache:** **q8_0**.

## Why Q8 (not BF16) MTP draft

On the upgrade stack, a **BF16 MTP draft + 128k/context crashes** (`Failed to allocate physical memory`, SIGSEGV — the draft's speculative buffer reserve exceeds the 32 GB card). Quantizing the draft to Q8 frees ~1.5 GB VRAM (draft load ~2.4 GB vs ~3.9 GB BF16) and makes 128k stable, with **acceptance unchanged**:
full-suite weighted acceptance **0.567** vs the BF16-baseline **0.5670** — no quality loss.

## Full launch flags

```bash
--m /models/Qwen3.8-27B-Q4_K_M.gguf \
--mmproj /models/mmproj-Qwen3.8-27B-Q8_0.gguf \
--no-mmproj-offload --image-min-tokens 1024 \
--n-gpu-layers 999 \
--ctx-size 131072 \
--cache-type-k q8_0 --cache-type-v q8_0 \
--flash-attn on \
--spec-type draft-mtp \
--spec-draft-model /models/mtp-Qwen3.8-27B-Q8_0.gguf \
--spec-draft-n-max 3 \
--spec-draft-p-min 0.1 \
--port 8080 --host 0.0.0.0
```

> The `examples/qwen27b-server.sh` launcher matches this configuration (Q8 MTP + Q8 mmproj + MTP3 + 128k + q8_0).

Required environment:

```bash
ONEAPI_DEVICE_SELECTOR=level_zero:0
SYCL_CACHE_PERSISTENT=0
ZES_ENABLE_SYSMAN=1
```

## Memory footprint

- Main model 18.9 GB + **Q8 MTP draft ~2.4 GB** + mmproj Q8 (~0.6 GB, CPU) + 128k q8_0 KV. Fits 32 GB with headroom.
- Decode ≈ **24–28 t/s** during long agent chains (≈8% above the ≈23.2 t/s no-draft baseline).
- Full-suite acceptance **0.567** (66 records, mean len 3.04) — matches the old BF16 MTP baseline.

## When to use / avoid

- **Use as the default** — enables 128k on the upgrade stack without the BF16-crash penalty.
- MTP on agent/tool-call chains is a *marginal* win (short per-turn generations eat the draft overhead); it shines on long contiguous generation. `nodraft-vision-128k` remains the option when speculation overhead is unwanted.
- Do **not** switch the draft back to BF16 on this stack at 128k — confirmed crash.
