## Why this test
`--spec-draft-n-max 4` (MTP4) shows a known **4th-position acceptance collapse** on agent/deep-context loads. Measured on the b10731 full suite: pos4 = **0.462** (median 0.44), worst in agent load (T3 deep 0.498 w/ turns as low as 0.15–0.28; T5 tool rounds 0.376). Question: drop to MTP3 to skip the dead 4th slot?

## Reading
- MTP3 decode t/s **higher on every task** (+11–29%), draft-acc higher everywhere (ALL 0.580 vs 0.514).
- **Wall clock decisive:** t3 23.6→**15.5 min** (−34%), t5 14.7→**11 min** (−25%). Even allowing run-to-run variance, the consistent per-task decode gains confirm it.
- Mechanism: MTP4 spends large compute drafting+verifying a 4th token that usually fails in agent loads (deep context / short tool rounds), and each phase is a heavier 4-wide batch. MTP3 drops the collapsed 4th slot → leaner phases, more compute to actual output.
- Honest caveat: request counts/prompt mix differ run-to-run (agent stochastic); not a perfectly matched n-per-task test. But decode + wall-clock + acceptance all move the same way → conclusion robust.

## Conclusion
**MTP3 is the recommended config for agent (dsh) production load on B70.** MTP4 remains the max-context extreme fallback (its 4th position only pays off on short, highly-predictable one-shot outputs like t1/t2 where pos4 = 0.65).
