## Summary

The combination of a **high-quality BF16 MTP draft (n=3), 96k context, and q8_0 KV** is the first llama.cpp SYCL configuration on B70 to pass all five benchmark tasks. `KV q8_0` fixes the MTP + long-context OOM that plagued f16 KV, and the high-acceptance MTP draft delivers speed *and* stability (no-draft was stable but slower).

## Environment

- GPU: Intel Arc Pro B70 (32 GB), `pcie_aspm=off`.
- Server container `b70-qwen27b-ggmlorg-mtp`, endpoint `:18080/v1`; full ggml-org stack.
- `--ctx-size 98304`, `--cache-type-k/v q8_0`, `--spec-type draft-mtp --spec-draft-n-max 3 --spec-draft-p-min 0.1`, `--n-gpu-layers 999 --flash-attn on`.

## What was fixed vs prior runs

### 1. MTP + long-context OOM root cause
With f16 KV, the 5.9 GB MTP draft + growing agent context blew up **host memory** (single-container peak 27.8 GB + 7.7 GB swap) → OOM killer.
**Fix:** `--cache-type-k/v q8_0` (halves KV).

### 2. Recurring card dropout
PCIe ASPM power management dropped the B70 off the bus.
**Fix:** kernel `pcie_aspm=off` (grub).

### MTP version comparison (same model stack)

| Config | KV | T4 | All 5 |
|--------|----|----|-------|
| MTP2/128K | f16 | ❌ OOM | 3/5 |
| MTP4/96K | f16 | ❌ OOM | 3/5 |
| MTP3/96K | f16 | ❌ OOM | 3/5 |
| **MTP3/96K** | **q8_0** | ✅ | **5/5 🏆** |

**Conclusion:** MTP OOM on agent loads is a **KV-cache space problem**, not a draft problem. Quantizing KV lets MTP cover a full long agent chain.

## vs no-draft

- No-draft 128k: decode ≈23 t/s, T3/T4/T5 3/3 stable but slower.
- **This config (MTP3/96K + q8_0): decode ≈33–35 t/s, 5/5.**
- Achieves **speed and stability together**.

## Conclusion

Recommended default configuration. For runs needing more than 96k context, use [mtp4-128k](./2026-08-21-mtp4-128k.md); watch host RAM and PCIe stability if pushing higher `n-max` or context.
