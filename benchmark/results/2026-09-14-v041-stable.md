## Detailed findings

### t1_html — PASS
41.4 tok/s decode (baseline 40.9), TTFT 0.67 s, 3582 completion tokens, 10451 characters of output, `</html>` properly closed. Acceptance 0.744.

### t2_svg — PASS
46.2 tok/s (baseline 46.3), TTFT 0.65 s, 7211 tokens, 16627 characters, `</svg>` properly closed. Acceptance 0.897 (the highest of this round).

### t3_security — PASS
Completed in 359 s (v0.4.0 was in the 342 s range) and produced a structured review: high-severity H1 (Web UI/API unauthenticated by default and bound to `0.0.0.0:8080`), H2 (`POST /api/import` does not validate the topic character set → arbitrary MQTT discovery messages can be injected), H3 (payload size cap / truncation), medium M1–M5, low L7 (`KnownFields`). Each item carries `file:line`, the risk rationale and a fix recommendation, and the report explicitly states that no Go toolchain was available, so the findings come from static reading. Decode 20.82 tok/s matches the 20.8 baseline; fill 472.3 is slightly better than 464; acceptance 0.532 vs 0.550 (−3%, but the per-block median is 0.941 — a few deep-context blocks pull the weighted figure down).
Decode is strongly context-depth dependent: t3 is a deep-context long-chain task, so its 20.8 tok/s is not comparable to the 41–46 tok/s of short tasks.

### t4_hostinfo — PASS (accurate data)
The output is valid JSON (keys: hostname/os/cpu/memory/disk/gpu/uptime/notes) and was verified against the real machine: Intel i5-7500T (4 cores), 14 GiB RAM (~7.7 GiB available) + 4 GiB swap, disk 457G at 47% (231G free). The container reports Debian 12 as its OS (that is the image OS; the host runs Ubuntu 26.04 — a reasonable statement from inside the container). The GPU is honestly reported as "not detected" (the harness host has no GPU; the model did not invent a B70). Every metric beats the baseline: fill 492.2 vs 430, decode 37.57 vs 35.9, acceptance 0.809 vs 0.803.

### t5_snowfall — PASS (with source caveat)
Completed in 477 s with 142 tool calls. Answer: **258.6 cm** for 2025-11-01 → 2026-09-14 (the range for which official daily data exists), explicitly noting that the requested range extends to 2026-12-31 and that no data has been published past mid-September.
**Independent verification**: the agent ultimately used Environment Canada `api.weather.gc.ca/collections/climate-daily` (station 49568 = YOW) and summed `TOTAL_SNOW`; querying the same API myself over the same window returns **258.6 cm (318 days)**, exactly matching the answer → the figure is reproducible from its stated source.
The difference from the v0.4.0 baseline (145.7 cm) is a **source difference, not an error**: that run used the Open-Meteo archive (ERA5 reanalysis, `snowfall_sum`), which I also reproduce as 145.7 cm for the same window. ECCC station observations run systematically higher than ERA5 reanalysis. Both are reproducible, but the **measurement basis differs**, so future t5 comparisons must fix the data source.
Metrics: fill 298.6 vs 293 baseline, TTFT 0.96/1.59 s vs 1.0/1.7 s, decode 33.93 vs 35.5 (−4%, because this task issued 142 short tool-call turns), acceptance 0.812 vs 0.724 (+12%).
