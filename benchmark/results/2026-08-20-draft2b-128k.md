# 2026-08-20 — draft2b-128k

- **Config:** [draft2b-128k](../configs/draft2b-128k.md)
- **Result:** Full pass — **3/3 agent tasks** (`EXIT=0`) for T3/T4/T5, plus single-shot reference numbers. Also fixes the catastrophic-slowdown KV overflow found earlier.

## Summary

This run validates the **q8_0 KV fix** and documents why a **2B draft is a net drag**. Switching the KV cache from f16 to `q8_0` + moving from a 4B to a 2B draft took the server from a disastrous **0.2 t/s** to **13.4 t/s**. llama.cpp SYCL became the **first B70 backend to complete all dsh agent tasks deterministically** (vLLM-MTP crashed on T5).

## Environment

- GPU: Intel Arc Pro B70 (32 GB). Host kernel: `pcie_aspm=off`.
- Server: `llama.cpp-sycl-b70:server` container, endpoint `:18080/v1`.
- Main model `Qwen3.8-27B-Q4_K_M.gguf` + draft `Qwen3.5-2B-Q4_K_M.gguf` (`draft-simple`, n_max 4), 128k context, KV q8_0.

## Metrics & caveats

- Real client-perceived rate from streaming `tg` ≈ **9–13 t/s**; llama.cpp's per-block `eval time` (33–143 t/s) is batched speculative throughput and is *not* the user-facing rate (see [METHODOLOGY §3](../METHODOLOGY.md)).
- Draft-acceptance metrics are aggregated `accepted/generated` from llama.cpp `draft acceptance` log lines, segmented by UTC window.

## Conclusion

**llama.cpp SYCL is the first B70 backend to deterministically complete all three agent tasks.** It trades single-shot speed for stability, which is the right trade for long agent/tool workloads. Practical split: llama.cpp for deterministic agent success, vLLM-MTP for throughput-tolerant benchmarks.
